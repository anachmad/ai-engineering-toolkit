# Phase 1 architecture

The shared playbook and versioned canonical standards are authoritative. Both project-local host entry points reference the same skill. The Python standard-library scaffolder consumes JSON-formatted YAML (a YAML subset) and shared templates. It resolves and reports the effective project path, rejects symlinks in generated paths below that root, preflights non-file conflicts, and preserves existing files. Ancestor symlinks are resolved rather than rejected. These path checks do not protect against concurrent replacement by a hostile process. Audit checks presence, not approval or actual gate compliance.

Native agent discovery, invocation, initialization and auditing were exercised with both installed hosts using disposable projects; results depend on the host environment. The manifest has a declarative versioned contract and the policy contracts are documented in `standards/schema-contracts.md`; checks are not full YAML or arbitrary JSON Schema validation. Phase 2 adds a local, non-executing router and security evidence evaluator; see `docs/phase-2-orchestration.md`. The manager, third-party installation, GitLab enforcement and vendor tooling remain later-phase work.
